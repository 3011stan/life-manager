# ADR 0007: API Contract Between Repositories

**Status**: Accepted (2026-10-04)
**Feature**: `002-cloud-foundation` — evidence in research R8

## Decision

- Route schemas defined with TypeBox in the API; OpenAPI generated by
  `@fastify/swagger` and committed as `openapi.json` in the backend repository.
- Backend CI regenerates `openapi.json` and fails on any difference, and runs a
  breaking-change check (oasdiff) against the base branch.
- Each backend release publishes its `openapi.json`. The frontend pins a spec
  version and generates its client with **orval** (version pinned):
  TanStack Query hooks plus types. The generated folder is never edited by hand;
  frontend CI regenerates it and fails on any difference.
- All generated calls go through one **custom mutator** in the frontend, which
  owns credentials, the idempotency key, error mapping, and the offline
  read-only guard (ADR 0006). Components do not call `fetch` directly.
- Contract changes follow expand/contract like schema changes: the API keeps
  accepting what the deployed web app sends until the web app is updated.

## Consequences

- orval output is larger than a types-only client; it is reviewed through the
  regenerate-and-diff check, not line by line.
- TanStack Query hooks from orval are the data layer that the offline cache
  persists, so query keys must stay stable across regenerations.

## Rejected

`openapi-typescript` + `openapi-fetch` (originally proposed; types only, no
hooks), Zod type provider (extra conversion layer), hey-api (0.x churn).
