# Data Model: Cloud Foundation

**Feature**: `002-cloud-foundation` | **Date**: 2026-10-04
**Sources**: [spec.md](spec.md), ADRs 0001, 0003, 0004, 0006

This is the logical model. Exact column types and migrations are written during
implementation and reviewed under ADR 0005.

## Conventions (every table holding workspace data)

From ADR 0004 and ADR 0006:

| Column | Rule |
|---|---|
| `id` | UUIDv7; may be generated by the client; primary key |
| `workspace_id` | Required; part of every foreign key to another workspace table: `(workspace_id, x_id)` |
| `created_at`, `updated_at` | Timestamps in UTC, set by the server |
| `version` | Integer, starts at 1, incremented on every update |
| `deleted_at` | Null unless soft-deleted (tombstone for future sync) |

- Row-level security is enabled and forced; the policy matches
  `workspace_id` against the per-transaction setting `app.workspace_id`.
- Unique constraints include `workspace_id`.
- Calendar days (none in this feature) are stored as dates plus the workspace
  time zone; instants as UTC timestamps.

Identity tables are **global** (not workspace-scoped): they are read and written
only by the authentication layer, never by workspace routes.

## Entities

### Account (identity, global)

The person who signs in. Stored in the authentication library's `user` table
(ADR 0003); referred to as **account** everywhere else.

| Field | Rules |
|---|---|
| `id` | Opaque identifier |
| `email` | From Google; unique; must be on the allow list when the account is created |
| `name`, `image` | From Google; optional |
| `email_verified` | From Google |
| `created_at`, `updated_at` | |

Related authentication tables (owned by the library, same database): `session`
(revocable; 30-day expiry with sliding refresh), `account_link` (the library's
`account` table: provider = google, provider account id), `verification`
(unused until magic link).

### Allowed Email (global)

| Field | Rules |
|---|---|
| `email` | Primary key; stored lower-case |
| `note` | Optional, owner's reminder |
| `created_at` | |

Managed directly by the owner (no screen in this feature). Checked before an
account is created (FR-002). Removing an entry blocks future sign-ins of that
address; existing data is kept.

### Workspace (tenant)

| Field | Rules |
|---|---|
| `id` | UUIDv7 |
| `created_at`, `updated_at`, `version`, `deleted_at` | Conventions |

Created automatically, together with its owner membership and default settings,
in the same transaction as the account's first sign-in (FR-003).

### Workspace Member

Links accounts to workspaces so sharing can be added later without moving data.

| Field | Rules |
|---|---|
| `workspace_id` | Workspace |
| `account_id` | Account |
| `role` | `owner` (only value in this feature) |
| `created_at` | |

- Primary key `(workspace_id, account_id)`.
- **Temporary constraint**: unique `account_id` (one workspace per account).
  Dropped by a later migration when sharing is introduced (constitution
  amendment required first).
- The authenticated request's workspace is resolved from this table, never
  from client input (FR-008).

### Workspace Settings (the walking-skeleton resource)

One row per workspace.

| Field | Rules | Default |
|---|---|---|
| `id` | UUIDv7 | |
| `workspace_id` | Unique | |
| `week_start_day` | Integer 0–6 (0 = Sunday) | 0 |
| `time_zone` | Valid IANA time zone name | Detected from the first device; `America/Sao_Paulo` if unavailable |
| `default_daily_capacity_minutes` | Integer 1–1440 | 960 |
| Conventions | `created_at`, `updated_at`, `version`, `deleted_at` | |

- Updates are field-level; the last saved value wins (spec US2 scenario 3);
  `version` is returned so a future offline outbox can detect conflicts.
- Invalid values are rejected and leave the row unchanged (FR-013).

### Security Event

| Field | Rules |
|---|---|
| `id` | UUIDv7 |
| `account_id` | Opaque account id; **not** a foreign key, so the event survives account deletion |
| `type` | `sign_in`, `sign_in_refused`, `sign_out`, `export`, `account_deleted` |
| `occurred_at` | UTC |
| `ip_hash` | Optional; salted hash, never the raw address |

- Contains no workspace content and no email (FR-027).
- `sign_in_refused` records only a salted hash of the refused email.
- Retained 90 days.

### Idempotency Key

Lets mutating requests be retried safely (ADR 0006).

| Field | Rules |
|---|---|
| `workspace_id` | Scope |
| `key` | Client-supplied; primary key `(workspace_id, key)` |
| `request_hash` | Hash of method, path, body; a reused key with a different body is rejected |
| `response_status`, `response_body` | Stored result returned on replay |
| `created_at` | Expires after 24 hours |

Workspace-scoped, so row-level security applies.

## Relationships

```
Allowed Email ┄┄(checked at first sign-in)┄┄> Account
Account 1 ── * Session
Account 1 ── * Account Link (provider)
Account 1 ── 1 Workspace Member ── 1 Workspace      (1:1 in this feature)
Workspace 1 ── 1 Workspace Settings
Workspace 1 ── * Idempotency Key
Account ┄┄(opaque id, no FK)┄┄ * Security Event
```

## Lifecycles

**Account**

1. *Not allowed*: sign-in refused, nothing stored except a refusal event.
2. *Created*: first sign-in of an allowed email creates account, workspace,
   membership, and default settings in one transaction.
3. *Active*: sessions created and revoked as the user signs in and out.
4. *Deleted* (FR-019, FR-020): after explicit confirmation, one transaction
   deletes the workspace (cascading to settings, membership, idempotency keys),
   the account, its sessions and provider links; an `account_deleted` event is
   written. Backups age out within 30 days.

**Session**: created on sign-in → refreshed on use → ends on sign-out, expiry
(30 days without use), or account deletion.

## Export Mapping (FR-017, FR-018)

The export contains every row above that belongs to the account, except
authentication secrets (session tokens, provider tokens) and security events
of other accounts. Format: [contracts/export-format.md](contracts/export-format.md).
